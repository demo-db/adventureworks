# AdventureWorks OLTP source and conversion

The source files are pinned from [`microsoft/sql-server-samples`](https://github.com/microsoft/sql-server-samples/tree/beaab06ef72831089ca80e5355d65e661fd19b26/samples/databases/adventure-works/oltp-install-script) at commit `beaab06ef72831089ca80e5355d65e661fd19b26`. `source-lock.json` records the SHA-256 of the installer, README, 69 CSV files, and upstream MIT license. The upstream AdventureWorks README identifies the OLTP installer as updated for SQL Server 2025; the pinned `AWBuildVersion.csv` contains build `17.0.1000.3`. The installer can also create a database for other SQL Server versions, so the version claim applies to these pinned fixture inputs.

Run `python3 scripts/rebuild-source.py` to create the deterministic gzip fixture `data-source/source.sqlite.gz`; `python3 scripts/rebuild-source.py --check` rebuilds in a temporary directory, verifies both the compressed and decompressed SHA-256 pins, and compares the complete logical SQLite schema, table rows, BLOB bytes, translated view definitions, and view results to the committed fixture. It also checks every pinned source-file hash, SQLite integrity, foreign keys, and source table/view counts. SQLite file bytes can vary by SQLite library version, so this check proves logical reproducibility; the provider manifest separately pins the committed compressed bytes.

The converter loads the 68 `BULK INSERT` source files and the pinned one-row `AWBuildVersion.csv`. `dbo.DatabaseLog` and `dbo.ErrorLog` have no static input file and remain empty; the installer uses them for runtime DDL audit and error logging. The original 20 SQL Server view definitions are preserved in `metadata/native-objects.json`. Eleven views use straightforward joins and projections and are translated to SQLite; nine use SQL Server XML methods, `CROSS/OUTER APPLY`, or `PIVOT` and remain source-only. No empty view substitutes or synthetic rows are added.

The conversion stores `xml` values as text, `geography` and `hierarchyid` values as opaque BLOB bytes, and preserves computed-column values from the source files as ordinary snapshot values while retaining each source expression in metadata. The SQLite fixture does not implement SQL Server XML, spatial, or hierarchy operations. SQL Server installation setup, triggers, stored procedures, Query Store, and optimized locking are not reproduced. `GETDATE()` defaults are frozen to the pinned build timestamp for reproducibility; source-seeded GUIDs remain unchanged. SQL Server `NEWID()` defaults are retained in native source metadata but omitted from SQLite DDL because SQLite only permits constant defaults; the committed fixture is a static snapshot. SQL Server primary-key nullability is preserved, including explicit `NOT NULL` where SQLite would otherwise permit NULL in a table-level key.

Fixed-width text values retain their source padding. Check expressions trim trailing spaces where SQL Server string comparison semantics require it, and the source's one-character `LIKE '[A-Za-z]'` check becomes the equivalent SQLite `GLOB` expression. Decimal, numeric, and money source text is parsed as Python binary floating-point values and stored with SQLite `NUMERIC` affinity; exact decimal scale and precision are not guaranteed, and this fixture makes no fixed-point `MONEY` claim. SQL Server collation and numeric behavior can differ from a SQL Server installation.

The installer has 71 tables, 20 views, 90 foreign-key constraints, 93 explicit indexes plus one inline unique constraint on Production.Document.rowguid. The data files contain 759,240 static rows; the two runtime audit/error tables are intentionally empty. SQLite file bytes can vary by SQLite library version, so the build check compares full logical contents and the provider manifest separately pins the checked-in fixture bytes. CSV cannot distinguish SQL `NULL` from empty text; SQLite and JSON preserve `NULL`. Binary JSON and CSV cells are base64 encoded.
